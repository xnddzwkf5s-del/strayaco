Time Machine Backups on a Synology NAS: What's Actually Changing (AFP, Not SMB)

Apple is deprecating AFP — the protocol behind Time Capsule-era backups. SMB remains fully supported. Here's what that means and how to set up Time Machine on your Synology NAS the supported way.

Time Machine NFS SMB Synology NAS macOS Backups Data Management

The Headlines

Apple deprecated the AFP (Apple Filing Protocol) client in macOS Sequoia 15.5, and plans to remove it entirely in a future macOS release (reported as macOS 27). That's what ends Time Machine support for AFP-based devices — most notably AirPort Time Capsules, and any old NAS shares still served over AFP.

To be clear: SMB is not being deprecated. SMB remains Apple's supported protocol for network Time Machine backups. If your Synology already serves Time Machine over SMB, you're on the right path — no migration needed. This guide covers what's actually changing, how to set up the supported SMB configuration, and what to do if you're still on AFP-era hardware.

Correction (8 September 2026): An earlier version of this article incorrectly claimed SMB support for Time Machine was going away and recommended migrating to NFS. That was inverted — AFP is the protocol being deprecated; SMB remains supported. The article has been rewritten accordingly.

What's Actually Changing: AFP, Not SMB

AFP is Apple's own legacy file-sharing protocol — it powered AirPort Time Capsules and early NAS-based Time Machine setups. Apple discontinued the Time Capsule hardware years ago, and with macOS Sequoia 15.5 the AFP client itself was formally deprecated, with removal planned for a future macOS (reported as macOS 27). Once that lands, Time Machine backups to AFP destinations simply stop working.

SMB is a different story. Apple moved network Time Machine to SMB years ago and continues to support it — including the server-side capabilities Time Machine relies on, which Synology's DSM implements. SMB is where Apple is staying, not where Apple is leaving.

What This Means for You

If your backup setup looks like this:

Mac → network → Synology NAS → SMB share → Time Machine

You're already on the supported path — nothing to do. But if it looks like this:

Mac → network → AirPort Time Capsule (or AFP share) → Time Machine

Then you have a ticking clock. The fix is to move those backups to an SMB share on a NAS — before a macOS update forces your hand. The migration isn't difficult, and once it's done, it just works.

What You'll Need

  • A Synology NAS (any model running DSM 7.x or later)
  • A Mac running macOS Ventura, Sonoma, or Sequoia
  • Admin access to both
  • A network connection between them (wired is better, Wi-Fi works)

Step 1 — Enable SMB on Your Synology

1. Open Control Panel → File Services → SMB

2. Tick Enable SMB service and click Apply

Step 2 — Create a Dedicated Time Machine Share

1. Open Control Panel → Shared Folder → Create

2. Name it something obvious like timemachine

3. Click Next through the defaults and finish creation

Step 3 — Enable Time Machine on the Share

1. Back in Control Panel → File Services → SMB, find the Time Machine section

2. Tick Enable Time Machine and select your timemachine shared folder

3. Set a quota — a good rule of thumb is 2–3× the size of your Mac's internal drive — and Apply

Why the quota matters: Without one, Time Machine will keep growing its backup until the volume is full. The quota caps it.

Step 4 — Point Time Machine at the Share

1. Open System Settings → General → Time Machine

2. Click Add Backup Disk (or the + button)

3. Select the Synology share — it appears automatically once Time Machine is enabled on it in DSM

4. Enter your Synology user credentials when prompted

5. Done. Time Machine will start its first backup within a couple of minutes.

Appendix: NFS as an UNSUPPORTED Community Workaround

Unsupported: macOS does not offer NFS mounts as Time Machine destinations — the System Settings disk picker only lists supported volumes (local disks and SMB shares). The steps below are a community workaround, not an Apple-endorsed path. They rely on undocumented behaviour that can break with any macOS update, and earlier versions of this article incorrectly presented NFS as the recommended migration. Use the supported SMB setup above unless you know exactly why you need NFS.

Some users still prefer NFS for technical reasons. If that's you, the broad strokes are: enable NFS in Control Panel → File Services → NFS, create a shared folder with NFS permissions covering your Mac's IP (Read/Write, no squash mapping), then mount it manually:

# Create a mount point
sudo mkdir -p /Volumes/timemachine

# Mount the NFS share (replace nas_ip with your Synology's IP)
sudo mount -t nfs -o resvport,locallocks nas_ip:/volume1/timemachine /Volumes/timemachine

That mount command won't survive a reboot — making it stick requires a Login Item, an /etc/fstab entry, or a LaunchDaemon:

echo "nas_ip:/volume1/timemachine /Volumes/timemachine nfs rw,resvport,locallocks,noatime 0 0" | sudo tee -a /etc/fstab

And because the Time Machine disk picker won't list NFS volumes, getting Time Machine to actually use one takes further undocumented tweaks — one more reason to treat this as an experiment, not a strategy.

What About Existing AFP / Time Capsule Backups?

If you have old AFP-based Time Machine backups (e.g. on a Time Capsule) you want to keep, here's the pragmatic route:

  1. Start fresh with SMB for ongoing backups
  2. Keep the old AFP volume around as an archive while it still mounts
  3. Once you're confident the SMB backups are working, you can retire the old backup

Time Machine will do a full initial backup to the new SMB share, so you won't lose coverage. And if your existing backups are already on SMB? Nothing changes — they keep working.

A Note on Performance

SMB over a wired Gigabit connection is solid for Time Machine. Wireless will work, but expect slower initial backups (especially the first one, which is always the biggest).

If you're on Wi-Fi, consider:

  • A 5 GHz connection (not 2.4 GHz)
  • Scheduling backups during off-peak hours
  • Using macOS's built-in throttling (it handles this well)

The Bottom Line

Apple deprecating AFP isn't a crisis — but it is a deadline if you're still running a Time Capsule or an AFP share. The move to SMB on a Synology NAS takes about 15 minutes of hands-on work, lands you on the protocol Apple actually supports, and once it's done, you can forget about it.
