Monitoring Home Appliances with Arlec Grid Connect Plugs + Tuya API + OpenClaw

Arlec Tuya Smart Plugs Energy Python OpenClaw Home Automation

How to extract energy data from cheap smart plugs without the vendor app, using an AI agent to collect, store, and report on your power usage.

Why Bother?

I was looking at my electricity bill — $1,600+ a quarter — and had no idea which appliances were the culprits. Was the ducted heating? The old fridge? The dryer running twice a week? I needed data, not guesses.

The Arlec Grid Connect smart plugs from Bunnings ($55 for a 4-pack) are the cheapest energy-monitoring smart plugs you can buy in Australia. They measure real-time power consumption and cumulative energy usage. But the default "Grid Connect" app is limited — no API, no automation, no way to pull data into anything useful.

Here's how I set them up to work with an AI agent (OpenClaw) to automatically collect, store, and report on appliance energy usage.

Step 1: Ditch the Grid Connect App

The Arlec plugs speak Tuya's protocol under the hood. The "Grid Connect" app is just a rebranded Tuya Smart Life app. Instead of using it, install Tuya Smart Life (or Smart Living) from the App Store.

  1. Download Tuya Smart Life from the App Store
  2. Create an account
  3. Plug in an Arlec plug, press and hold the button until the LED flashes rapidly
  4. The app will find it. Add each plug.
  5. Give them sensible names (Fridge, Coffee Machine, Dishwasher, etc.)

This step is critical because the Tuya platform accounts are what give you API access. Grid Connect accounts won't let you create API keys.

Step 2: Set Up the Tuya IoT Platform

Now you need to give your AI agent API access to read the plug data.

  1. Go to iot.tuya.com and sign in with the same account you used in the app
  2. Click Cloud → Create Cloud Project
  3. Name it whatever you like ("Home Energy Monitor")
  4. For Development Method, select Smart Home
  5. For Data Center, pick the one that matches your region (typically Central Europe for Australia — the app auto-assigns this)
  6. Once created, you'll see your Access ID and Access Secret — save these

Then link the plugs to the project:

  1. In the cloud project, go to Devices → Link Devices by App Account
  2. Scan the QR code with the Tuya Smart Life app on your phone
  3. This authorises the project to access all devices in your Tuya account

You should now see your 4 plugs listed under Devices with their Device IDs.

Step 3: The Local Key

Each plug has a local key that lets you query it directly on your local network without going through the cloud. This is faster and more reliable.

The easiest way to get these keys is with the tinytuya scan tool:

pip3 install tinytuya
python3 -m tinytuya.scan

This broadcasts UDP discovery and will list all Tuya devices on your network with their IPs, IDs, and local keys. Save them in a JSON file:

[
  {
    "name": "Plug 1 - Fridge",
    "id": "abc123def456abc123def4",
    "key": "abc123def456abc123def4",
    "ip": "192.168.1.100"
  },
  {
    "name": "Plug 2 - Coffee Machine",
    "id": "789ghi012jkl345mno678p",
    "key": "789ghi012jkl345mno678p",
    "ip": "192.168.1.101"
  }
]

And your Tuya cloud credentials in a separate file:

{
  "apiRegion": "eu",
  "apiKey": "your_tuya_access_id_here",
  "apiSecret": "your_tuya_access_secret_here"
}

Step 4: The Energy Collection Script

Here's the script that runs every 6 days and queries each plug directly over your local network — no cloud dependency needed. The tinytuya library sends a UDP discovery broadcast to find each plug, then reads the cumulative energy counter (DPS 25) straight off the device over TCP.

#!/usr/bin/env python3
"""
Energy Data Collector — Local Tuya polling.
Query plugs for cumulative energy total (DPS 25), store snapshots, compute deltas.
"""

import os, json, sqlite3
from datetime import datetime, timedelta, timezone
import tinytuya

WORKSPACE = os.path.expanduser("~/.openclaw/workspace")
PLUGS_PATH = f"{WORKSPACE}/data/grid_connect_devices.json"
DB_PATH = f"{WORKSPACE}/data/energy_monitor.db"
AEST = timezone(timedelta(hours=10))


def query_device(dev_id, ip, local_key):
    """Poll device locally via tinytuya. dps 25 = cumulative energy in Wh."""
    d = tinytuya.Device(dev_id=dev_id, address=ip,
                        local_key=local_key, version=3.5)
    d.set_socketTimeout(5)
    data = d.status()
    if data and "dps" in data:
        return data["dps"].get("25", 0)
    return None

The script then:

  1. Reads the device list from grid_connect_devices.json (the file we saved in Step 3)
  2. For each plug, queries it directly over the local network
  3. Stores a weekly snapshot (cumulative Wh) in SQLite
  4. Computes the delta from the previous week (kWh consumed that week)
  5. Calculates cost at your current electricity rate

Step 5: Automate with OpenClaw

Rather than running the script manually, I have an AI agent (OpenClaw) running it on a cron schedule.

Active Cron Jobs

JobScheduleWhat it does
Energy — Data CollectionEvery 6 daysRuns energy_collect.py --force to pull cumulative energy from all 4 plugs
Energy — Monthly Report1st of each monthGenerates an HTML report and emails it to my inbox

The AI agent handles all the orchestration: spawns a lightweight isolated session, runs the Python script, checks the exit code, and reports errors if anything fails. This means I never have to SSH in or run commands — the agent just handles it.

What I Learned

I combined two data sources for this: the smart plugs gave me per-appliance breakdowns, while 15 months of half-hourly data from my Origin Energy bill showed the whole-house picture. Here's what stood out:

The always-on base load is small. Fridge + modem + standby electronics = ~200W continuous. That's about $1.20/day. (From the smart plugs.)

The big swings are seasonal. My mild-weather baseline is 22-28 kWh/day. Winter with ducted heating? 40-57 kWh/day. Summer with AC? 39-43 kWh/day. The heating/cooling load adds $5-12/day in extreme weather. (From Origin whole-house data — the plugs only monitor individual appliances, not the ducted system.)

The biggest appliance shocks (all from the smart plugs):

  • Electric hot water without an off-peak timer → 8-12 kWh/day ($3-4/day)
  • Oven vs air fryer → oven draws 3 kW for 45 min vs air fryer at 1.5 kW for 20 min. That's $0.50-0.80 saved every time you swap
  • Dryer → 2-3 kWh per cycle, costing $0.70-1.30 per load. Clothes rack = free.

Database Schema

The script creates a SQLite database with three tables:

-- Weekly cumulative snapshots from each plug
CREATE TABLE weekly_snapshots (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    device_id TEXT,
    week_start TEXT,
    total_energy_wh INTEGER,
    timestamp TEXT,
    UNIQUE(device_id, week_start)
);

-- Computed consumption deltas (kWh per week)
CREATE TABLE weekly_consumption (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    device_id TEXT,
    device_name TEXT,
    week_start TEXT,
    week_end TEXT,
    consumption_kwh REAL,
    cost REAL,
    UNIQUE(device_id, week_start)
);

-- Monthly aggregated report data
CREATE TABLE monthly_reports (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    month TEXT,
    generated_at TEXT,
    total_kwh REAL,
    total_cost REAL,
    data_json TEXT
);

Improvements I'd Make

Real-time monitoring. The current setup polls every 6 days. If you want to catch short-duration appliances (kettle, microwave, toaster), you need polling every 5-15 minutes. The local tinytuya protocol supports this, but you're trading off WiFi chatter for granularity.

PostgreSQL instead of SQLite. If you're running this at scale, SQLite handles concurrent writes poorly. The monthly report generation collides with the collection script. A proper PostgreSQL database would be more robust.

Zigbee instead of WiFi. Arlec also makes a Zigbee range that pairs with a hub. Zigbee plugs consume less power themselves and don't crowd your WiFi. The downside is you need a hub (like Home Assistant or a Tuya Zigbee gateway).

Tuya Cloud API limits. The free tier has rate limits. Weekly polling is fine, but if you scale to real-time, you'll hit them. Consider a local-only approach with tinytuya direct polling if you need higher frequency.

What You Need to Run This

  1. Hardware: 4 × Arlec Grid Connect Smart Plugs — $55
  2. App: Tuya Smart Life (not Grid Connect)
  3. Platform: Tuya IoT — free account
  4. Software: Python 3 + pip install tinytuya
  5. AI Agent: OpenClaw or any cron-triggered script runner
  6. Total cost: $55 (the plugs) — everything else is free
