OpenClaw on DigitalOcean with Tailscale Serve

19 July 2026 — AI / Infrastructure / DevOps

This week I set up OpenClaw on a DigitalOcean droplet with Tailscale Serve for secure remote access. It should have been straightforward. It wasn't — but every dead end taught us something. This post captures the complete working setup, every gotcha we hit, and a one-command fix script you can use yourself.

1. The Stack

  • Host: DigitalOcean Basic Droplet (1 vCPU, 1 GB RAM, 25 GB SSD, ~$6/mo)
  • OS: Ubuntu 24.04 LTS
  • AI Agent: OpenClaw 2026.7.x
  • Model: DeepSeek V4 Flash (via API)
  • Network: Tailscale + Tailscale Serve (tailnet-only HTTPS)

2. The One-Command Setup

Assuming you've already created a DO droplet (SSH key, Ubuntu 24.04) and SSH'd in as root:

# Step 1: Bootstrap the droplet
apt update && apt upgrade -y
curl -fsSL https://deb.nodesource.com/setup_24.x | bash -
apt install -y nodejs
curl -fsSL https://openclaw.ai/install.sh | bash

# Step 2: Create the openclaw user + swap
adduser openclaw
usermod -aG sudo openclaw
loginctl enable-linger openclaw
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

Then run the fix script (it handles everything from here):

curl -fsSL https://strayaco.com.au/fix-openclaw-access.sh | bash
This script is also mirrored at realform.com.au/fix-openclaw-access.sh.
Important: Tailscale must also be installed on your laptop — download from tailscale.com/download. Log in with the same account on both devices.

Once the script completes, open the URL it prints (something like https://yourhostname.ts.net/) in your browser. With Tailscale identity headers, it should authenticate you automatically — no token needed.

3. Every Gotcha We Hit

🔥 Gotcha #1: Tailscale must be on BOTH machines

This sounds obvious in hindsight, but we spent the longest time debugging the droplet when the issue was simply that the laptop didn't have Tailscale installed. The error messages from the Gateway are generic — "could not connect" could mean anything from a wrong port to a missing client.

Fix: Install Tailscale on your laptop too. Same account, same tailnet.

🔥 Gotcha #2: Browser needs HTTPS for WebSocket

When you access the Gateway over plain HTTP (not localhost), the browser's WebSocket connection fails with: control ui requires device identity (use HTTPS or localhost secure context). This is a browser security requirement — WebSocket connections from insecure contexts are restricted.

Fix: Use Tailscale Serve (provides HTTPS via https://hostname.ts.net/) or SSH tunnel (http://localhost:18789). Do not bind the gateway directly to the public internet.

🔥 Gotcha #3: tailscale serve needs operator permissions

When OpenClaw starts with gateway.tailscale.mode = serve, it tries to run tailscale serve to set up the HTTPS proxy. By default, the openclaw user doesn't have permission to do this. The gateway logs an error: Access denied: serve config denied.

Fix: tailscale set --operator=openclaw grants the openclaw user permission to manage Serve/Funnel.

🔥 Gotcha #4: gateway.bind and tailscale.mode are a PAIR

Tailscale Serve requires gateway.bind = loopback. If gateway.bind is explicitly set to lan or tailnet while tailscale.mode = serve, the gateway will refuse to start with a validation error. But if gateway.bind is simply unset (the default), the gateway starts silently and binds to the Tailscale IP instead of loopback — it works, but Tailscale Serve is proxying to the wrong interface.

Fix: Always set both together, even if you think the default is fine: openclaw config set gateway.bind loopback and openclaw config set gateway.tailscale.mode serve.

🔥 Gotcha #5: Don't set controlUi.allowedOrigins manually

With Tailscale Serve, the gateway auto-seeds controlUi.allowedOrigins with ["http://localhost:18789", "http://127.0.0.1:18789"]. If you manually set it to your public IP (as we did during troubleshooting), the gateway will reject the Tailscale MagicDNS origin. Tailscale identity headers handle origin verification automatically.

Fix: Leave controlUi.allowedOrigins unset when using Tailscale Serve. The gateway handles it.

🔥 Gotcha #6: gateway.auth.allowTailscale skips the token prompt

When gateway.auth.allowTailscale is true, Tailscale identity headers authenticate you automatically — no need to paste the gateway token. This only works for the Control UI WebSocket path, not API calls.

Fix: Enable it: openclaw config set gateway.auth.allowTailscale true.

🔥 Gotcha #7: systemctl --user via SSH needs DBUS

Running systemctl --user restart openclaw-gateway.service as root over SSH fails with Failed to connect to bus: No medium found. The systemd user bus isn't available in that context.

Bonus gotcha: systemctl --machine=openclaw@.host works for restarting services, but journalctl --machine=openclaw@.host does not work on a default DO Ubuntu droplet — it needs systemd-container to be installed. You'll get: Failed to open root directory of machine 'openclaw@.host': The name org.freedesktop.machine1 was not provided by any .service files.

Fix (restart): Use systemctl --machine=openclaw@.host --user restart openclaw-gateway.service or set DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/$(id -u openclaw)/bus. Fix (logs): Use the DBUS approach: DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/$(id -u openclaw)/bus journalctl --user -u openclaw-gateway.service -n 50.

🔥 Gotcha #8: The URL has NO port

Tailscale Serve proxies port 443 (HTTPS) to localhost:18789 on the droplet. The browser URL is https://hostname.ts.net/ — no port number. Adding :18789 to the end won't work because Tailscale Serve doesn't expose that port.

4. How the Fix Script Works

The script at strayaco.com.au/fix-openclaw-access.sh (mirrored at realform.com.au) automates all of the above. Here's what it does, step by step:

  1. Detect the user. Checks /root/.openclaw/, /home/openclaw/.openclaw/, and current user to find the right config.
  2. Install & connect Tailscale. Installs via apt, runs tailscale up, captures the MagicDNS hostname.
  3. Enable HTTPS on the tailnet. Checks tailscale serve status and enables HTTPS if not already done.
  4. Set tailscale operator. Runs tailscale set --operator=openclaw so the gateway can manage Serve.
  5. Read or generate a gateway token. Parses the JSON config directly with python3, falling back to openclaw doctor --generate-gateway-token.
  6. Clear stale allowedOrigins. Removes any manually set controlUi.allowedOrigins (Tailscale Serve handles this).
  7. Enable allowTailscale. Sets gateway.auth.allowTailscale = true for auto-login.
  8. Configure Serve mode. Sets gateway.bind = loopback paired with gateway.tailscale.mode = serve.
  9. Restart the gateway. Uses the DBUS-safe --machine flag or manual fallback.
  10. Verify. Checks the gateway responds on port 18789 and Tailscale Serve is mapped.
  11. Print a health report. PASS/WARN/FAIL per check, the access URL, and the token.

The script is idempotent — safe to re-run if something goes wrong.

5. FAQ & Troubleshooting

Q: The script says "Tailscale NOT connected"

Run sudo tailscale up — it will print a URL to authenticate in your browser. Then re-run the script.

Q: I can reach the URL but get an auth prompt

If allowTailscale isn't working (unlikely), enter the gateway token from the script output. If you see "rate limited", wait 30 seconds and try again.

Q: Can I use this without Tailscale?

Yes — use an SSH tunnel: ssh -L 18789:localhost:18789 root@<droplet-ip>, then open http://localhost:18789/. This works on any machine with SSH access, no Tailscale needed.

Q: What if the gateway doesn't restart?

SSH into the droplet and run: systemctl --machine=openclaw@.host --user restart openclaw-gateway.service. Check logs with: DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/$(id -u openclaw)/bus journalctl --user -u openclaw-gateway.service -n 50 (the --machine flag for journalctl requires systemd-container which isn't installed by default on DO).

Q: What about reboots?

Tailscale auto-starts via systemd. The OpenClaw gateway auto-starts via systemd user service + loginctl enable-linger openclaw. A droplet reboot should result in everything coming back up. The script verifies both.
